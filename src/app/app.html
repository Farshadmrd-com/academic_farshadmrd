@if (isProjectOpen('basil-tracker')) {

A permissioned blockchain application that tracks basil from origin to consumer across multiple organizations. Built with a Hyperledger Fabric network, a Spring Boot gateway, and an Angular frontend.

Security highlights

  • Permissioned network with PKI identities: every participant (Org1, Org2, peers, ordering service) is issued an X.509 certificate by a Fabric CA, so only authenticated and authorized members can transact.
  • Immutable, tamper-evident ledger: each basil record is cryptographically chained on the Fabric ledger, making historical data non-repudiable and protecting against silent record tampering.
  • Multi-party endorsement & consensus: transactions must be endorsed by independent organizations before being ordered and committed, eliminating any single point of trust or compromise.
  • Chaincode-enforced business rules: all writes flow through smart contracts that validate input and enforce access control at the ledger layer, instead of trusting the client.
  • Hardened gateway boundary: the Spring Boot backend isolates the Fabric Gateway SDK from the public API, applies CORS rules, and shields wallet credentials from the browser.
  • End-to-end auditability: every create / query operation produces a traceable transaction with an origin (country) field, supporting full provenance audits for food-supply integrity.

A Python implementation of the Mondrian Multidimensional K-Anonymity algorithm (LeFevre, DeWitt, Ramakrishnan) for privacy-preserving data publishing. Anonymizes tabular datasets such as the UCI Adult dataset so that individual records cannot be re-identified through table-joining attacks.

Privacy highlights

  • Formal k-anonymity guarantee: every released record is indistinguishable from at least k − 1 others on its quasi-identifiers, blocking linkage attacks against auxiliary datasets.
  • Multidimensional partitioning: the Mondrian algorithm splits the quasi-identifier space adaptively, preserving more data utility than single-dimensional generalization.
  • Explicit identifier suppression: direct identifiers (names, IDs) are removed before generalization, separating PII handling from utility-preserving transformations.
  • Configurable risk vs. utility trade-off: the k parameter and sensitive-attribute exclusion let operators tune the privacy/utility balance for each release.
  • Quality measurement: a c-avg metric quantifies information loss, making the anonymization auditable rather than opaque.
